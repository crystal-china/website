## 通知功能

  全新环境通过 `bin/tasks db.migrate` 创建完整结构，无须执行用户名或正文 HTML
  回填。尚未升级的旧站点须先按[历史升级要求](用户名与提及.md#现有环境升级)使用
  压缩前版本完成升级，再切换当前版本。

  提及解析规则改变后，应停止服务器，使用新版本任务运行：

  ```bash
  bin/tasks db.rebuild.content_html
  ```

  重建包含软删除的主题和评论，只更新正文 HTML，不修改编辑时间，不补发或撤销历史
  通知。完成后再启动服务器。

  ### 使用与通知规则

  登录用户可以点击导航栏铃铛，在弹窗中查看通知，每页二十条。新增回复会通知主题作者
  和被直接回复的用户，排除发送者本人，并避免同一次操作给同一个人重复发送。

  在 Markdown 编辑器中输入 @ 后至少两个字符，会在停止输入约 250 毫秒后查询自动补全，
  每次最多返回八个用户。只搜索 login_name，大小写不敏感；候选同时显示昵称和登录用户名。
  每次发布或编辑最多通知五个被提及用户。编辑时可以通知新提及的用户，但同一内容已经
  发送过的同类型通知不会重复发送。

  回复和提及通知按 (user_id, url, kind) 去重。因此，一个人之前收到回复通知，后来又
  被明确提及，仍然可以收到提及通知。

  允许明确 @自己，但普通的自我回复不会通知自己。

  用户可以在“编辑我的信息”中关闭“接收 @提及通知”。关闭后，不再接收任何人的提及通
  知，包括管理员和自己，同时不再出现在 @ 自动补全结果中。正常回复通知、管理操作通
  知及历史通知不受影响。重新开启后恢复显示；当前用户开启此设置时，也可以搜索到自
  己。

  正文只为前五个不同的合法登录用户名生成提及链接，大小写不同的同一用户名只占一个
  名额，重复提及不额外占名额，超限部分保留为普通文字。通知使用实际生成链接的用户名
  名单，再筛选存在且允许接收提及通知的用户；链接本身不要求该用户一定存在。

  @ 前可以紧接中文或下划线，例如 hello_@zw963 可以补全并生成提及；紧接 ASCII 字母、
  数字或另一个 @ 时不识别。`\@zw963` 是普通文字，不补全、不生成链接，也不发送提及
  通知。连续反斜杠为偶数时表示普通反斜杠，此后的 @ 仍可被识别。

  代码、已有链接、图片说明、HTML 属性、手写 HTML 的链接和代码等容器，以及 info
  提示框中的 @ 不生成用户链接或提及通知。用户改名后，旧正文中的提及及链接不会改写。

  铃铛显示未读数量，超过九十九条显示 99+。页面加载时更新状态，停留在页面期间通过
  在线人数心跳每两分钟更新一次，不保证别人刚回复后立即显示。打开通知列表或全部标为
  已读后，也会同步更新铃铛。

  打开通知列表不会自动标为已读；点击通知才标为已读。也可以通过“全部标为已读”批量
  处理；没有未读通知时，该按钮不可用。

  点击评论通知后，会加载评论所在的正确分页，必要时展开子评论，再滚动并高亮目标评
  论。该流程通过 comment_id 参数和 Hyperscript 实现，不依赖 URL 锚点。

  管理员编辑主题或评论、移动主题到其他节点，或者删除内容时，作者会收到通知。一次操
  作中修改主题标题或正文算作一条编辑通知；移动主题会记录目标节点名称。这些管理事件
  在不同操作之间不去重。自己编辑、移动或删除自己的内容不会通知自己。

  ### 数据与历史记录

  每条通知保存来源标题，以及原始 Markdown 前 120 个字符的快照，作为普通文本显示。
  移动主题的通知使用目标节点名称作为摘要。

  显示通知时不加载来源记录。后续编辑、软删除不会改变已有快照；编辑中新增加的提及通
  知，保存编辑后版本的快照。

  actor_id 保存实际操作者，例如编辑或删除内容的管理员，而不是内容作者。操作者通过
  关联预加载，因此用户改名后，通知显示其当前名字。

  每条通知保存站内相对 URL，不保存目标记录关联。评论 URL 使用 /comments/:id，打开
  时会定位评论当前所在的分页。

  目标已删除或不可访问时，显示友好的 404 页面，并提供进入社区和文档的链接。即使目标
  被物理删除，历史快照仍然保留。

  创建回复和提及通知前，Crystal 代码会检查是否已有同类通知。非唯一的 (user_id,
  url, kind) 索引用于加速检查；管理操作通知不执行这一去重检查。
