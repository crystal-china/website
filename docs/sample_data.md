## 前言与第一篇主题

两个评论区都有以下场景。正文中的 `【…】` 标记便于识别，也可以用于回收站关键词过滤。

| 场景 | 检查内容 |
| --- | --- |
| 最早的长讨论 | 引用、列表、代码、info 提示框、四层回复和投票；根评论及较早的子评论在倒序第二页 |
| 可以删除，也可以撤回 | 小明没有回复的评论，同时显示两种操作；其他普通用户不能操作 |
| 已撤回的根评论 | 紧凑卡片隐藏正文和投票，但仍能展开后代；作者和管理员可以恢复 |
| 子评论撤回演示 | 中间评论已撤回，投票和后代保留；删除它的唯一直接回复后，父评论可删除 |
| 回复已删除，父评论可删除 | 历史回复不再阻止作者删除；恢复一条回复后重新受限 |
| 整支级联删除 | 三层评论同批删除；回收站可查看同批记录，并按父子顺序逐条恢复 |
| 更早单独删除 | 保留旧删除时间，不混入后来的批次；`100%`、`a_b`、反斜杠可测试字面搜索 |
| 只删除中间分支 | 被删分支的后代不可访问，兄弟分支和根评论仍可见 |
| 部分恢复 / 同批只剩一条 | 根和父评论已恢复，孙评论仍删除；不显示父评论链接或同批入口 |
| 撤回但没有回复 | 紧凑卡片既可恢复，也可直接删除 |
| 提及与 Markdown | 五人上限、下划线用户名、中文紧跟提及、代码／手写链接／转义跳过、iframe 清洗 |
| 作者编辑 / 删除后已恢复 | 编辑标记、缓存 HTML 同步、恢复后楼层不变，以及重新删除和撤回 |

管理员进入 `/admin/trash`：有超过一页的已删除评论；不同批次且尚未恢复的父评论可以跨分页定位。同批记录原地展开，最多两层，内部翻页不改变地址栏；关键词搜索仍用于外层列表。
撤回与软删除不同：撤回保留正文和投票，软删除后普通入口返回不可用页面。

## 通知与辅助主题

小明有 36 条通知，分两页，每页均包含九种类型；日期分散到三天，含已读和未读状态。
准备场景时产生的通知会通过普通删除清空，保留逐行 trigger 对总数和未读计数的维护。
新回复、编辑和提及主要来自前言与第一篇主题；其中两条提及来自编辑旧子评论，可测试两级分页定位，另有一条提及指向已撤回的评论。

第二篇主题用于关注通知：小明不是作者，只关注主题。第一篇同时测试作者通知覆盖关注通知，不重复发送。
四篇已删除的辅助主题用于删除通知；其中一篇保留可预览的根评论及单独删除的子评论，可以检查主题未恢复时拒绝恢复评论。

社区保留 21 篇可见主题以测试第二页，其他主题大多无回复。前言取真实 Markdown 文件内容；主题标题和正文包含“配置”“PGroonga”等搜索词。
管理员与小明保留多年分布的账户事件；小明另有个人介绍、最后活跃时间和累计在线时长。
