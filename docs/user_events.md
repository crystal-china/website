# 用户事件记录

`UserAudit` 现在保存用户事件，统一入口是 `/user_audits`，每页条数直接使用 `App::SMALL_PER_PAGE`（当前为 10），最新事件排在最前面。个人主页的“账户记录”链接通过 `user_id` 指定目标用户，显示该账户的个人记录页；仅本人和管理员可以查看，普通用户请求查看其他人的记录会返回 403。

管理员从后台侧栏的“账户记录”进入 `/user_audits`，不传 `user_id` 时显示全站记录；普通用户不传该参数时仍只显示自己的记录。两者使用同一个页面：全站记录显示后台左侧导航，并选中“账户记录”；个人记录保持居中、不显示后台侧栏，包括管理员查看指定账户的情况。个人记录页头显示目标账户和“回到个人主页”，全站记录通过左侧导航切换后台页面。全站列表中的每条记录紧凑显示头像、所属账户和事件，时间放在右侧；个人列表不重复显示账户身份。本人操作不再重复显示“操作人”，管理员代操作或操作者未知时仍显示。事件、字段变更详情和不同操作者放在同一行，窄屏自然换行。已删除账户的历史仍然保留，显示原账户 ID。

记录页采用普通页面布局，没有面板限高或内部滚动条，每页最多完整显示 10 条记录，分页在列表底部。后台记录撑满右侧内容区，个人记录限宽居中。后台页头只显示筛选栏；个人页头只显示账户和返回按钮，不再显示重复标题和说明。翻页仍局部替换记录与分页，并回到页面顶部。

全站记录可按完整登录用户名（不区分大小写）和事件类型筛选，两者可以组合使用。留空用户名并选择“所有事件”可查看全部记录；找不到用户名时显示空结果。分页保留筛选条件，重新提交搜索从第一页开始。搜索的是记录所属账户，不是操作者；个人记录页不显示或应用这组筛选。

用户名输入至少两个字符后，延迟 250 毫秒按前缀查找，最多显示 8 个候选，选择后填入完整用户名。候选显示昵称和登录用户名；↑/↓ 切换候选，回车或鼠标点击确认当前高亮项，Esc 关闭；无须输入 `@`。正文提及默认高亮第一项，Tab 确认候选，Shift+Tab 离开；账户搜索先用方向键选中，Tab 和 Shift+Tab 始终正常切换表单焦点，不填入候选。账户搜索与正文提及共用自动补全 JS 和 `/htmx/users/autocomplete` 接口：管理员可查找所有用户，包括关闭提及通知或隐身的用户；普通用户的候选仍排除关闭提及通知的用户。能查找到不代表强制通知，发送提及时仍尊重接收者的通知设置。补全失败时仍可手动输入完整用户名搜索。

- `ProfileChanged`：修改昵称或登录用户名，记录字段名和变更前后的值。
- `PasswordChanged`：通过个人设置或找回密码修改密码，只记录事件和时间，不保存密码、确认密码或哈希。
- `OauthSignedIn`：每次成功的第三方登录，记录平台名称和时间，不保存令牌。
- `PasswordSignedIn`：每次成功的密码登录，只记录事件、用户和时间，不保存密码。失败登录、普通页面访问及刷新会话不产生此事件。
- `PasswordRemoved`：管理员移除本站密码，禁用密码登录并使旧会话失效，不删除账号。

`user_id` 是记录所属的用户，`actor_id` 是实际操作者。本人操作时两者相同；管理员修改他人资料或密码时，记录管理员为操作者。两个 ID 都不设置数据库外键，账户删除后仍保留原 ID，界面显示未知或已删除账户及其 ID。

Model 将两侧都声明为可空关联，列表使用 Avram 的 `preload_user`、`preload_actor`，不再手动组装用户 Hash。为了兼容关联对象已经不存在的情况，数据库中的两个 ID 字段允许为空；正常写入仍由 `SaveUserAudit` 校验两个 ID 必填，创建记录未指定操作者时默认本人。历史记录中已经为空的操作者不会被猜测或补写。

可空关联和无外键设计已合并进初始建表 migration；当前版本没有单独放宽约束的增量 migration。新环境和历史数据库的处理方式见下方部署说明。

个人设置中的“上次修改密码”来自最近一次 `PasswordChanged` 或 `PasswordRemoved` 事件。没有历史记录时显示“暂无密码修改记录”，不以注册时间冒充修改时间；没有记录不代表当前一定没有密码。

普通用户的登录用户名仅能在注册后的前 7 天修改，不是每隔 7 天修改一次。超过期限后字段只读，服务端也会拒绝修改；昵称、头像、密码不受此限制。管理员不受改名期限限制，但同样必须通过格式、长度和唯一性校验。账户记录使用相对时间（如“5 分钟前”），悬停可查看完整时间。

本人和管理员从用户主页的“编辑个人资料”进入 `/users/:id/edit`，统一通过 `PUT /users/:id` 保存。仅本人或管理员可以访问；操作者由服务端传入，不接受浏览器指定。保存成功后直接重新渲染编辑页，保留编辑页地址，并用新的 Operation 清空密码框；导航栏使用更新后的当前用户对象。仅编辑本人时刷新当前登录会话，管理员编辑他人时仍保持管理员身份。

管理员可使用“上次修改密码”后的“移除密码”按钮；它是独立提交，不保存表单中其他尚未提交的改动。成功后局部替换密码状态区域，更新时间、移除按钮和成功提示，不离开编辑页。

签名 `tagline` 和个人介绍 `bio` 保存在 `users.profile` JSONB 中，默认 `{}`。签名最多 80 个字符，个人介绍最多 3000 个字符，均以纯文本展示，不解析 Markdown 或发送提及通知。个人主页显示两者，社区作者卡片只显示签名；未填写的字段不显示。头像、签名和个人介绍修改不写入账户事件。

旧的 `@用户名` 链接暂不随改名更新；目标不存在时返回 404。

## 在线用户与隐身

页脚显示在线用户和游客人数。登录后点击在线用户人数可打开名单，查看头像、昵称和登录用户名，并进入个人主页。名单在每次打开时查询，表示最近 3 分钟收到心跳的公开用户；现有心跳每两分钟发送一次，不提供实时推送。游客只能查看人数，不能读取名单。

游客按 IP 去重，人数只是估计值，例如同一公网 IP 下的两位访客会合并计为一位。累计在线时长按连续心跳间隔估算，后台标签页也可能继续发送心跳，不代表实际专注阅读的时长。待写回数据每五分钟落库，个人页显示的累计值可能滞后；进程退出前尚未落库的部分也可能丢失。

在个人资料编辑页勾选“始终隐身”后，账号不计入公开在线人数，也不出现在名单中。主页和作者卡片不再显示活跃时间和累计在线时长，对所有查看者统一隐藏，包括本人。后台仍正常累计在线时长，设置不影响回复、提及或通知，也不产生账户事件。关闭隐身后，下次心跳恢复公开展示。

隐身偏好保存在 `users.hide_online_status`，默认不隐身。累计在线秒数保存在 `users.online_seconds`，默认从 0 开始，不补算历史数据。在线缓存属于当前服务进程，重启后随心跳重新建立。

## 会话失效

`users.session_version` 在密码修改或移除时轮换，与密码在同一条 SQL 中保存。浏览器会话和 API 令牌都必须匹配数据库中的当前版本，因此旧凭据在下一次请求时被拒绝。不会主动关闭已经打开的页面，也不能撤销已经通过身份验证、正在处理的请求。

本人改密、重置密码成功后，当前浏览器换发新会话并继续登录；其他旧会话和 API 令牌失效。管理员修改他人密码不影响管理员自己的登录。昵称、头像等普通修改及失败的保存不轮换版本。

版本轮换集中在 `User::SaveOperation#changes`，覆盖现有所有密码保存入口。不要通过 Query 批量更新或直接 SQL 修改密码，否则会绕过这一逻辑。

首次记录 OAuth 登录时，如果账号已有本站密码，会提醒用户确认该密码是否由本人设置。历史 OAuth 登录没有记录可回填，因此这里判断的是启用事件记录后首次记录的登录。

用户事件表、操作者关联、会话版本、累计在线秒数和隐身偏好已合并进初始建表 migration。全新环境先执行 `bin/tasks db.migrate`，再运行 `bin/tasks db.seed.required_data` 创建默认 Space 和社区节点，无须额外回填任务。

已执行完整历史迁移的数据库无需重新建表，不需要删除 `migrations` 表中的历史版本。尚未升级的旧数据库必须先使用压缩前版本完成迁移和必要任务，再切换到当前版本；当前初始 migration 不会替旧表补字段。历史升级曾清空旧 audit 表，并使不带会话版本的旧登录会话及 API 令牌失效，这些步骤不会因本次压缩而再次执行。

密码事件分别由 `UpdateUser`、`ResetPassword` 的保存回调写入，与用户修改处于同一事务；OAuth 事件在回调验证并获得用户后写入。今后新增密码修改入口时，也应写入同类事件。
