# 用户名与提及

## 用户字段

`nickname` 是显示昵称，可以包含空格，不要求唯一。

`login_name` 是登录和 `@提及` 使用的唯一用户名，大小写不敏感。保存时保留原始大小写，但 `Billy` 和 `billy` 指向同一个用户。自动补全只搜索 `login_name`，同时显示昵称和登录用户名，选中后插入 `@login_name`。

`login_name_lower` 是 PostgreSQL 自动维护的存储生成列，保存小写形式，用于唯一性检查和查询，不改变 `login_name` 的原始大小写。表单、Operation、Factory 和 seed 都不要给它赋值。

## 注册和个人设置

邮箱注册必须填写登录用户名，长度为 2 到 20 个字符。采用参考 Discourse 的 ASCII 字符规则：

- 只能包含英文字母、数字、下划线 `_`、连字符 `-` 和点号 `.`。
- 必须以英文字母、数字或下划线开头，以英文字母或数字结尾。
- 特殊符号不能连续出现，包括 `._` 等不同符号的组合。

昵称可以不填，留空时默认使用登录用户名；昵称可以包含中文、空格和 emoji。手动注册时，如果登录用户名已被占用，会提示错误，不会自动改成其他名字。

个人设置使用同样的规则。清空昵称后，也会恢复为登录用户名。

## OAuth 注册和密码登录

新用户通过 GitHub 注册时，优先使用 GitHub 的登录用户名作为本站 `login_name`。Google 则使用提供方返回的 nickname 或显示名生成。

生成时会移除不支持的字符，将连续特殊符号合并成一个下划线，并清理非法的开头和结尾。结果不足两个字符时，生成 `Crystalist_` 加六位随机数字的用户名。如果名称被占用，会重新添加六位随机数字后缀。包括冲突后缀在内，总长度不超过 20 个字符。

提供方返回的显示名会保留为昵称。已经注册的 OAuth 用户再次登录时，保留现有的本站个人资料。

密码登录支持邮箱或大小写不敏感的 `login_name`，不支持用昵称登录。账号输入前后的空白会被忽略，但密码不会被裁剪。只有 OAuth 登录方式的账号，需要先设置密码才能使用密码登录；密码重置仍使用邮箱。

## 提及识别与通知

Markdown 解析前，会临时保护提及候选，避免用户名中的下划线与后面的文字一起被解析成斜体。`@login_name.` 末尾作为标点的点号不属于用户名。

`@` 前可以紧接中文或下划线，例如 `请@zw963`、`hello_@zw963`；紧接 ASCII 字母、数字或另一个 `@` 时不识别。自动补全使用相同的前置字符规则，用户名输入至少两个字符后开始查询。

`\@login_name` 是普通文字，不生成提及链接或通知，也不触发自动补全。判断的是 `@` 前连续反斜杠的数量：奇数个表示转义，偶数个表示普通反斜杠，此后的 `@` 仍可被识别。

通知使用本次渲染实际生成链接的用户名名单，只处理正文中前五个不同的用户名，大小写不同但实际相同的名字只占一个名额。代码、已有链接、图片说明、HTML 属性和 `info` 提示框中的提及不会触发提及通知。

旧的非 ASCII 登录用户名需要通过 `db.fix.login_names` 修复，昵称保持不变。用户更改登录用户名后，历史正文中的提及及链接不会自动改写，旧链接可能不再指向该用户。

## 现有环境升级

用户名拆分、规范化生成列和索引已合并进初始建表 migration。全新环境直接执行：

```bash
bin/tasks db.migrate
```

已完成历史升级的数据库不需要重新执行用户名修复。尚未执行用户名拆分的旧数据库，应先使用压缩前的版本，按该版本的步骤完成字段迁移、`db.fix.login_names` 和唯一索引创建，再切换到当前版本；不能仅用当前初始 migration 升级旧表。

历史修复任务会保留昵称，修复非法登录用户名和大小写不敏感的重名。该过程不会重写历史正文中的提及链接。全新数据库不需要运行此任务。

以前已被修改的 OAuth 昵称不会自动恢复，用户可以在个人设置中自行修改。修复或更改登录用户名不会重写旧帖子里的提及。
