# 国际化与翻译

本项目使用 Rosetta 的编译期翻译，以及官方 `Rosetta::Lucky.integrate` 和 `Rosetta::AvramBackend`。默认语言为 `zh-CN`，同时提供 `en`。翻译文件只在编译时读取，不会在每次请求中读 YAML。

## 从哪里开始读

1. `config/rosetta.cr`：语言配置、官方 Lucky 集成，以及针对当前 Avram/Rosetta 版本的两处兼容处理。
2. `config/rosetta/app.zh-CN.yml` 中的 `sign_ins.new_page` 与 `src/pages/sign_ins/new_page.cr`：最简单的页面翻译示例。
3. `config/rosetta/avram.zh-CN.yml`：表单字段和 Avram 标准校验。
4. `src/utils/validation_errors.cr`：字段错误和 flash 共用的格式化，以及字段翻译的编译期检查。

## 页面和组件

推荐直接使用官方短方法，不再增加一层翻译封装：

```crystal
class SignIns::NewPage < AuthLayout
  def page_title : String
    r("common.sign_in").t
  end

  def content : Nil
    para r(".description").t
  end
end
```

```yaml
zh-CN:
  sign_ins:
    new_page:
      description: "使用邮箱或登录用户名和密码登录你的账号。"
```

以 `.` 开头的 key 由类名推导：`SignIns::NewPage` 对应 `sign_ins.new_page`。页面自己的文案用相对 key；多个页面共用的按钮用 `common.*`，字段名用 `fields.*`。

翻译文件只分三组，每组包含 `en` 和 `zh-CN` 两个文件：

- `app.*.yml`：站点页面、组件、邮件和前端提示。
- `avram.*.yml`：字段名、Avram 标准校验和项目自定义校验。
- `rosetta.*.yml`：Rosetta 日期、时间和相对时间格式。

文件名不参与翻译 key 的解析，真正的 key 来自 YAML 内部层次。`app.*.yml` 仍保留 `forum`、`sign_ins` 等命名空间，不需要按类或组件拆文件。

继承的 Layout 方法和跨类使用的 mixin 使用完整 key，避免把父类文案错误解析到子类。泛型组件需要固定前缀时，使用官方注解，例如 `Forum::TopicFields(T)` 上的 `Rosetta::Translatable::Config(prefix: "forum.topic_fields")`。

## 插值和数量

```yaml
zh-CN:
  common:
    page_number: "第 %{page} / %{total} 页"
```

```crystal
r("common.page_number").t(page: pages.page.to_s, total: pages.total.to_s)
```

普通插值接受字符串；`count:` 接受数字，并支持官方复数规则。英文数量使用 `one`、`other`，中文只需要 `other`。不要拆分或拼接完整句子来翻译，也不要给缺失 key 提供静默英文 fallback。

## 字段和校验

`avram.en.yml` 与 `avram.zh-CN.yml` 中的字段名只维护一次：

```yaml
zh-CN:
  fields: &fields
    email: "电子邮件"
    password: "密码"
  avram:
    attribute_variants: *fields
    validate_required: "不能为空"
    error: "%{field} %{message}"
```

`&fields` 是 YAML anchor，`*fields` 引用同一组字段。这让静态表单可以写 `r("fields.email").t`，而动态字段错误仍遵循官方 `avram.attribute_variants` 约定，不复制两份字段名。

标准校验保持 `validate_required`、`validate_uniqueness_of` 等 Avram 用法，由配置好的官方 backend 取得对应 `avram.validate_*` 翻译。项目自己的校验消息放在 `validations.*`：

```crystal
login_name.add_error r("validations.login_name_format").t
```

字段旁的错误和失败 flash 都调用 `ValidationErrors.format`，使用当前语言，不再按英文原句反查中文。`Shared::Field` 未指定 label 时，也使用同一份字段目录。

当前依赖有两处缺口，因此在 `config/rosetta.cr` 集中兼容：

- Avram 参数类型转换会直接添加英文 `is invalid`，没有调用 i18n backend；在错误创建时将这一条框架 fallback 转为当前语言。
- Rosetta 1.0 的官方 adapter 没覆盖 Avram 新增的 URL 校验，并且数值边界使用 `%d` 会截断小数；保留官方 adapter，只补这三个分支。

这不是通用的英文消息反查表，也没有修改 `lib/`。将来上游补齐后，可以删除对应兼容代码。

## 如何切换语言

浏览器访问 `/sign_in?locale=en` 或任意正常页面的 `?locale=zh-CN`。选择保存在 session 中，后续普通请求和 HTMX 请求沿用它。无需给 users 表加语言字段；不支持的语言参数返回 400。

API 同样支持 `locale` 参数，但 API 禁用响应 cookies，因此应在每次请求中指定，不依赖浏览器式记忆。找不到路由的错误页也会读取语言参数或现有 session。

测试或后台代码可使用官方作用域：

```crystal
Rosetta.with_locale(:en) do
  Rosetta.find("fields.email").t
end
```

用户昵称、节点名称、主题内容、Markdown 文件和已经保存的通知快照不自动翻译。此次重构不改变这些数据，也不触发通知或修改编辑时间。

## 时间、邮件和前端

相对时间使用 `time_in_words` shard，通过 `relative_time(at)` 根据当前语言选择 shard 的 `EN` 或 `ZH_CN`。两种语言都直接调用 `from(time: at)`，由 shard 返回完整的过去时间表达，不再由 Rosetta 拼接后缀。

浏览器只通过 `src/js/timeZone.js` 获取设备的 IANA 时区名称（如 `Asia/Shanghai`），保存到本站的 `time_zone` Cookie。不会额外发送请求或自动刷新页面。首次访问还没有 Cookie 时使用服务器时区；后续普通请求和 HTMX 请求自动携带 Cookie。

服务端统一由 `HTTP::Server::Context#time_zone` 解析并缓存本次请求的时区。没有 Cookie、名称无效或服务器缺少对应时区数据时，回退 `Time::Location.local`（进程 `TZ`，未设置则为系统时区）。不改变全局 `TZ`，不同访问者的设置互不影响。

页面通过 `time_in_zone(at)` 转换时间，再自行格式化日期或详细时间。`local_time(at, label)` 只输出 `<time>`，并用相同时区生成悬停 `title`，显示文字由调用方提供。正文和悬停时间均由服务端渲染，不再使用逐标签转换的 JS 或 `data-local-time-*` 标记。相对时间仍按实际时间差计算；数据库时间和用户资料不变，排班表仍按固定业务时区运行。

邮件的主题、HTML 和纯文本模板同样使用 Rosetta。前端提示在 `javascript.*` 中维护，由 `Shared::Translations` 通过编译检查过的 lookup 输出为 JSON。`src/js/i18n.js` 只负责读取和插值，不保存第二套译文。

前端 JSON 放在 body 中，HTMX 整页替换时一并更新；只缓存当前 JSON 节点，避免切换语言后沿用旧提示。已经保存到 HTML 的 info 提示框标题由浏览器根据当前语言更新，不需要重建历史正文。

## 检查与维护

- 缺少 key 或插值参数：Rosetta 编译报错。
- 两个语言包缺少对应 key、插值或复数分支：Rosetta 编译报错。
- 给 Model 或 Operation 增加字段但忘记补字段名：`ValidationErrors.check_fields` 编译报错。
- 前端 JavaScript 使用的翻译 key：由 Bun 测试检查与服务端导出一致；JavaScript 调用本身不属于 Crystal 编译器的检查范围。

运行 `crystal spec spec/specs` 检查服务端。运行 `bun test ./spec/js/i18n.test.js ./spec/js/mentions.test.js` 检查前端；显式写 `./` 可避免 Bun 扫描本地克隆的其他项目。编译失败用例位于 `spec/fixtures/i18n/`，由测试验证它们确实无法编译。

本次 i18n 重构不需要新增 migration、回填数据库或重建正文 HTML。部署仍需正常重新编译应用和前端资源，因为 YAML 在编译时嵌入。
